# AGENTS.md

**Lexio** is an AI flashcard app: it turns English lesson PDFs or pasted text into English→Polish flashcards with spaced review. Product scope lives in `context/foundation/prd.md`, and stack rationale lives in `context/foundation/tech-stack.md`. Read the PRD before building features. Built on the 10x Astro Starter; so far it has auth, AI flashcard generation (`POST /api/ai/proposals`), flashcard storage, and the lesson flow at `/generate` from pasted text or a PDF (`src/components/lesson/LessonGenerator.tsx`; PDF text is extracted in the browser by `src/components/lesson/PdfLessonInput.tsx` and `src/lib/pdf/`; the review draft is kept per user in localStorage via `src/lib/review-draft.ts`), plus the profile page `/profile` (CEFR level and AI model, saved via `POST /api/profile`) whose level groups "too easy" proposals into a collapsed group in the review (`src/components/lesson/TooEasyGroup.tsx`).

## Hard rules

- **Supabase migrations**: `supabase/migrations/` (create new ones with `npx supabase migration new <name>`) using naming format `YYYYMMDDHHmmss_short_description.sql`. Always enable RLS on new tables with granular per-operation, per-role policies. Migrations are additive only and reach production by a manual `npx supabase db push` before the code that needs them. Table, function and key names other slices rely on are listed in `docs/reference/contract-surfaces.md`.
- **Flashcard data**: read and write flashcards only through `src/lib/services/flashcards.service.ts` (one card per word per user; saving an existing word only adds tags). A reviewed lesson is accepted via `POST /api/proposal-sets` (`src/pages/api/proposal-sets.ts`), which calls the `accept_proposal_set` SQL function: it saves accepted cards and writes one `proposal_outcomes` row per proposal in one transaction. Write outcome records only through `accept_proposal_set`; `proposal_outcomes` is append-only (no update/delete). `src/db/database.types.ts` is generated by `npm run db:types` — never edit it by hand.
- **Profile data**: read and write profiles only through `src/lib/services/profiles.service.ts` (one row per user: CEFR level and AI model, both nullable; a stored model that is no longer configured reads as `null`). Generation uses the profile's model when the request names none.
- **"Too easy"**: defined only by `isTooEasy` in `src/lib/ai/cefr.ts` (AI CEFR estimate strictly below the user's level, word not already in the collection). Bulk-rejected items are recorded as `rejected_too_easy` through `accept_proposal_set`.
- `src/lib/supabase.ts` — creates a Supabase SSR client using `@supabase/ssr` with cookie-based sessions. Uses `astro:env/server` for `SUPABASE_URL` and `SUPABASE_KEY` (server-only secrets declared in astro.config.mjs `env.schema`). Both are `optional`, and `createClient()` **returns `null` when they are missing**. The app still boots, with auth disabled and a banner driven by `src/lib/config-status.ts`. Every caller must handle the `null` client (see `src/pages/api/auth/signin.ts`).
- **API routes**: use uppercase `GET`, `POST` exports; validate input with zod (already a dependency). The existing auth endpoints don't validate input yet.
- Auth endpoints are plain HTML form POSTs that answer with redirects (errors go in the `?error=` query param), not JSON.
- **pdf.js is browser-only**: `pdfjs-dist` is loaded only through `src/lib/pdf/browser.ts`, via `await import(...)` inside an event handler guarded by `if (import.meta.env.SSR) return;`. Never import it (or `browser.ts`, or a `?url` worker import) statically from a component — a plain dynamic import in a `client:load` island still lands in the server (Worker) bundle. `npm run check:client-only` guards this.
- **Never write to `context/archive/`.** Archived changes are immutable. If a target path starts with `context/archive/`, stop with: "This change is archived. Open a new change with `/10x-new` instead."

## Commands

Standard scripts (`dev`, `build`, `preview`, `lint`, `lint:fix`, `format`) are in `package.json`. Not obvious from there:

- `npm run smoke` — dependency-free auth-flow smoke test (`scripts/smoke.mjs`) against a running server, `BASE_URL` env (default `http://localhost:4321`). Run after dependency upgrades.
- `npx astro check` — type-check `.astro`/`.ts` files. CI order: `astro sync` → lint → `astro check` → build, plus a smoke job against the production preview with a local Supabase (see `.github/workflows/ci.yml`). The CI build needs the `SUPABASE_URL` and `SUPABASE_KEY` repo secrets.

- `npm run db:types` — regenerate `src/db/database.types.ts` from the running local Supabase (`supabase gen types typescript --local`). Run after every migration and commit the result.
- `npm run check:rls` — two-user RLS isolation and one-word-per-user check (`scripts/check-rls.mjs`) against local Supabase; needs `SUPABASE_URL` / `SUPABASE_KEY` env (values from `npx supabase status -o env`). CI runs it in the smoke job.
- `npm run check:client-only` — fails if pdf.js code reached the server bundle (`scripts/check-client-only.mjs` scans `dist/server`); run after `npm run build`. CI runs it in the ci job after the build.
- `npm test` — Vitest unit tests (`src/**/*.test.ts`, config in `vitest.config.ts`); no network or API key needed. Import `describe`/`it`/`expect` from `vitest` explicitly (no globals). Modules under test must not import `astro:*`. CI runs it after lint.

## Architecture

### Auth flow

- `context.locals.user` is typed in `src/env.d.ts`. Add new `Locals` fields there.
- `src/middleware.ts` — runs on every request, resolves the current user, attaches to `context.locals.user`. Redirects unauthenticated users away from routes listed in `PROTECTED_ROUTES`.
- Auth routes and pages: see the "Auth routes" table in `README.md`.

### Key conventions

- **Astro vs React**: write a `.tsx` component only if it uses state, effects or event handlers (`useState`, `useEffect`, `onClick`, form handling). Everything else is `.astro`. Mount islands with `client:load` (as in `src/pages/auth/signin.astro`).
- **Tailwind class merging**: use the `cn()` helper from `@/lib/utils` (clsx + tailwind-merge) for conditional/merged class names. Do not concatenate class strings manually.
- **shadcn/ui**: configured in `components.json`. Add components with `npx shadcn@latest add <name>`.
- **React**: no Next.js directives ("use client" etc.). Extract hooks to `src/components/hooks/`.
- **Services vs helpers**: code that does I/O (Supabase queries, LLM calls) and is called from API routes goes in `src/lib/services/<domain>.service.ts` (e.g. `flashcards.service.ts`). Pure helpers without I/O go in `src/lib/`.
- **Shared types** (entities, DTOs) go in `src/types.ts`.

### Environment

- Env vars, local Supabase, `.dev.vars` and deploy: see `README.md` ("Getting Started", "Supabase Configuration", "Deployment").
- `OPENROUTER_API_KEY` (optional server secret in `astro.config.mjs` `env.schema`; Worker secret in production via `npx wrangler secret put OPENROUTER_API_KEY`). Without it `POST /api/ai/proposals` returns 503 and the config banner shows OpenRouter as missing. The selectable models live in `src/lib/ai/models.ts`.
